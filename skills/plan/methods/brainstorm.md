# Brainstorm

Use when there are many possible directions and little shape: what to build next, how to attack a problem, names, approaches.

## Steps

1. **The question.** One sentence, with the constraint that matters (time, money, platform, the owner's standing decisions). Ask the owner only if the question itself is unclear.
2. **Diverge.** Produce many options quickly, without judging. Use two or three lenses deliberately, for example:
   - *Reverse:* how would we make the problem worse? Invert each answer.
   - *Analogy:* how do two unrelated fields solve the same shape of problem?
   - *Constraints:* what if it had to be done in a day, with no code, for ten times the users?
   - *Users:* what would each user in `PLAN.md` ask for, and what would they never say?
   - *Remove:* what could we delete instead of add?
   Aim for 15–30 raw options. Several independent views help here: [roundtable.md](roundtable.md).
3. **Cluster.** Group the options into a handful of directions; name each.
4. **Converge.** Score each direction against the owner's goals and constraints (effort, value, risk, reversibility), from evidence where you have it. Drop the weak ones with one line why.
5. **Hand over.** The two or three strongest directions with their trade-offs and your recommendation, as one card when the owner chooses. Keep the raw list in `plan/references/<topic>/brainstorm.md` when it may be useful later.
